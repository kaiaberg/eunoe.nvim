1. INTRODUCTION                                                  *eunoe-intro*

eunoe shows a coding agent's conversation, your earlier prompts and the
agent's replies, in a split. Claude Code is built in.

When you press `Ctrl+G` in Claude Code to write a prompt in Neovim, the
conversation disappears behind the editor. |:Eunoe| brings it back next to
the prompt, so you can read it, jump between turns and quote from it while
you write. It also works as a side panel next to an agent running in
another terminal or tmux pane.

eunoe only reads the agent's transcript files on your machine. It sends
nothing anywhere and never changes the transcript.

==============================================================================
2. SETUP                                                         *eunoe-setup*

Requirements: Neovim 0.11 or newer, Claude Code with Neovim as its editor,
and `ps` (to find the agent Neovim was started from).

Claude Code opens the editor from `$VISUAL`, then `$EDITOR`, so set: >sh
  export VISUAL=nvim
<
|eunoe.setup()| is optional; call it only to change the defaults
(|eunoe-config|). eunoe maps no global keys. To open it with a key, map
|<Plug>(eunoe-toggle)|: >lua
  vim.keymap.set("n", "<leader>e", "<Plug>(eunoe-toggle)")
<
Run |:checkhealth| `eunoe` to check the setup. It also shows which session
eunoe finds from where you run it, and warns when the agent's transcript
format looks changed.

==============================================================================
3. THE CONVERSATION SPLIT                                        *eunoe-split*

|:Eunoe| opens a vertical split on the right with every turn of the
session (or the last few, |eunoe-config-turns|), newest at the bottom,
scrolled to the latest reply. Your cursor stays where it was, e.g. in the
prompt; go to the split with |CTRL-W_l| to use its keys or quote from it
(or set |eunoe-config-view| `focus`). Each message sits in a box with a
heading: >
  ╭─ 6 · You ─────────────────────────────────────────── 09:30
  │ Can you make the parser skip system reminders?
  ╰────────────────────────────────────────────────────────────
  ╭─ 6 · Claude ────────────────────────────────────────────────
  │ Yes. Three changes: …
  ╰────────────────────────────────────────────────────────────
<
The numbers let you and the agent mean the same turn ("turn 6, point 2").
The reply heading names the agent ("Agent" if its reader gives no name).
Each heading has an icon before the name (left out in these examples),
the box and heading have the speaker's color (|eunoe-highlights|), and the
prompt's heading shows the time on the right. The box is open on the
right, so long code lines don't break it. With `view.style = "bar"` a bar
`▎` runs along each message instead (|eunoe-config-view|). What the
headings show is configurable (|eunoe-config-heading|).

The box, the icons and the time are drawn on top of the text (the box's
left side in 'statuscolumn'), and the box needs no extra lines: its top
is the heading line, its bottom the blank line between messages. The buffer
line is just `6 · You`, so search for `6 ·` to find turn 6, and yanking
copies no icons. The headings aren't Markdown `#` headings: Markdown
renderers such as render-markdown.nvim would restyle those. The buffer
is otherwise read-only Markdown: search it, yank from it, and use your
Markdown plugins. Its name is `eunoe://<reader>/<session id>`.

Before the first prompt of a session there is no transcript yet, and the
split says "No conversation yet".

When you're done with the prompt, `:wq` as usual: the split closes with it
and Neovim exits (|eunoe-config-view| `auto_close`).

                                                                  *eunoe-keys*
Keys in the split (buffer-local, see |eunoe-config-keys|):

  `]]` `[[`     Next / previous turn heading.
  `R`         Reload: read the session again, e.g. after the agent wrote
              more, or after `/clear` or `/resume`.
  `o`         One line per message, and back (|eunoe-modes|).
  `O`         Everything open, and back.
  `q`         Close the split.
  `>`         Visual mode: quote the selection into the prompt
              (|eunoe-quote|).

The usual fold commands open and close truncated text and messages: |za|,
|zo|, |zc|, |zR| (everything open), |zM| (one line per message).

==============================================================================
4. WHICH SESSION IT SHOWS                                      *eunoe-session*

Started from the agent: after `Ctrl+G`, Neovim runs as a child of Claude
Code. eunoe walks up Neovim's parent processes and shows the session of the
nearest agent among them. This is the right one however many agents run.

Next to the agent: otherwise eunoe looks for sessions running in Neovim's
current directory. If there are several, it asks which one with
|vim.ui.select()| and remembers the choice.

Every |:Eunoe| and `R` reads the session again, so `/clear` and `/resume`
are followed.

==============================================================================
5. LONG PROMPTS AND REPLIES                                   *eunoe-truncate*

Prompts and replies longer than 800 characters (|eunoe-config-truncate|)
show their beginning; the rest sits in a closed fold: >
  … 1,615 more characters (za to expand)
<
The cut lands at the end of a line and never inside a fenced code block.
The newest reply stays open, since it is usually the one you are
answering; its fold still exists, so |zc| closes it.

                                                                  *eunoe-wrap*
Lines longer than 80 characters, or wider than the window
(|eunoe-config-wrap|), are broken at spaces into several buffer lines, so
long paragraphs can fold too. Code blocks and tables stay as they are, list
items indent their continuation lines, and quotes repeat `>`. Yanking with
|y| copies these line breaks; quoting (|eunoe-quote|) does not.

                                                               *eunoe-oneline*
                                                                 *eunoe-modes*
Modes ~

Every message is a fold, from its heading to the blank line after it,
with the truncation fold inside. The split has three modes, which are fold
levels ('foldlevel'):

  Mode        Level   Shows                          Keys
  `oneline`     0       one line per message           `o`, |zM|
  `default`     1       messages, long text folded
  `expanded`    2       everything open                `O`, |zR|

`o` and `O` switch to their mode, and back to the mode before when it is
on. The cursor stays on its message. `keys.cycle` (unset by default, e.g.
`"<Tab>"`) goes through the modes in the order above. |:Eunoe-mode| and
|eunoe.mode()| switch to a mode by name, and |eunoe-config-view| sets the
mode the split opens in. After that, the mode is kept when you press `R`
or open the split again.

In one-line mode each message shows its heading and the start of its
text, up to |eunoe-config-wrap| characters or the window width: >
  6 · You     Can you make the parser skip system reminders?
  6 · Claude  Yes. Three changes: skip the tags, keep the order, and…
<
Use it to skim a long session or find a message, then press `o` or |za|
on it. Searching with |/| opens the messages that match ('foldopen').
In one-line mode the newest reply is folded too. Expanded mode shows
everything, e.g. to read a whole session or search it.

==============================================================================
6. QUOTING INTO THE PROMPT                                       *eunoe-quote*

Select text in the eunoe split and press `>` (|eunoe-config-keys|). eunoe
inserts it as a `>` blockquote in the window you came from, the prompt: on
a blank line at the cursor, or below the cursor line if it has text. The
cursor then waits on the line after the quote, ready for your comment: >
  > Three changes: skip the tags, keep the order, and drop empty turns.

  Why drop empty turns?
<
The quote uses the original text, not the folded or wrapped lines on
screen. A characterwise selection (|v|) quotes exactly what is selected, a
linewise one (|V|) whole lines. Headings are left out. A selection over
closed folds quotes everything in them, e.g. whole messages in one-line
mode.

Quote short passages. The agent already has the conversation, and every
quoted line is sent again.

7. COMMANDS                                                   *eunoe-commands*

                                                                      *:Eunoe*
:Eunoe                  Open the split, or close it when it is open.

                                                                  *:Eunoe-all*
:Eunoe all              Open the split with every turn of the session, also
                        when |eunoe-config-turns| is set. `R` keeps showing
                        all of them.

                                                                 *:Eunoe-mode*
:Eunoe mode [{mode}]    Switch to `default`, `oneline` or `expanded`
                        (|eunoe-modes|), opening the split if it is closed.
                        Without {mode}, show the current mode.

:checkhealth eunoe      Check Neovim, the options, the process lookup, the
                        readers and the current session (|eunoe-health|).

8. MAPPINGS                                                   *eunoe-mappings*

eunoe maps no global keys. The keys inside the split are |eunoe-keys|.

                                                        *<Plug>(eunoe-toggle)*
<Plug>(eunoe-toggle)    Normal mode: like |:Eunoe|.

                                                         *<Plug>(eunoe-quote)*
<Plug>(eunoe-quote)     Visual mode: quote the selection into the prompt
                        (|eunoe-quote|). Works in the eunoe split only; the
                        split maps it to `>` already.

9. CONFIGURATION                                                *eunoe-config*

                                                               *eunoe.setup()*
eunoe.setup({opts})
    Optional. Merges {opts} into the defaults below. Unknown options and
    wrong values are reported with |vim.notify()| and again by
    |:checkhealth| `eunoe`.

The defaults: >lua
  require("eunoe").setup({
    turns = nil,
    view = {
      width = 0.4,
      focus = false,
      auto_close = true,
      wrap = 80,
      style = "box",
      bar = "▎",
      mode = "default",
    },
    keys = {
      close = "q",
      next_turn = "]]",
      prev_turn = "[[",
      reload = "R",
      quote = ">",
      oneline = "o",
      expanded = "O",
      cycle = false,
    },
    truncate = {
      chars = 800,
      prompt = nil,
      reply = nil,
      open_latest = true,
    },
    heading = {
      number = true,
      separator = true,
      icons = {
        user = "\u{f007}", -- nf-fa-user
        agent = nil,
      },
      names = true,
      time = true,
      pad = true,
    },
  })
<
                                                          *eunoe-config-turns*
turns ~
    How many turns |:Eunoe| shows, the newest; `nil` shows all of them.
    |:Eunoe-all| always shows all of them. Even long sessions open fast:
    eunoe reads the whole transcript anyway, and showing all turns only
    adds the rendering.

                                                           *eunoe-config-view*
view.width ~
    Width of the split: a fraction of the editor's columns (below 1) or a
    number of columns.

view.focus ~
    Move the cursor into the split when it opens. Off by default: the
    cursor stays where it was, e.g. in the prompt.

view.auto_close ~
    When you quit the last other window of the tab page (|:q|, |:wq|,
    |ZZ|, `:q!`), close the split too, so Neovim exits, or the tab page
    closes if there are others. Without it, `:wq` in the `Ctrl+G` editor
    leaves Neovim running with only the split, and the agent keeps
    waiting. Only quitting counts: |:close| and |:only| don't. Unsaved
    changes in hidden buffers still stop Neovim from exiting, as for any
    |:q|.

view.style ~
    `"box"`: a box around each message, open on the right, in the
    speaker's color. `"bar"`: a bar next to each message instead. Both
    take two columns on the left ('statuscolumn').

view.bar ~
    The bar's character (1 column) in bar style and for messages folded
    to one line. `false` turns the bar and its column off in bar style.

view.mode ~
    The mode the split opens in: `"default"`, `"oneline"` or `"expanded"`
    (|eunoe-modes|). After you switch, the split keeps your mode.

                                                           *eunoe-config-wrap*
view.wrap ~
    Break lines longer than this many characters into several lines
    (|eunoe-wrap|), or at the window's width if it is narrower. `false`
    keeps lines as they are. At least 20.

                                                           *eunoe-config-keys*
keys ~
    Keys in the split, buffer-local: `close`, `next_turn`, `prev_turn`,
    `reload`, `quote` (Visual mode), and for the modes (|eunoe-modes|)
    `oneline`, `expanded` and `cycle` (unset by default). `false` leaves a
    key unmapped.

                                                       *eunoe-config-truncate*
truncate ~
    Long prompts and replies show their beginning; the rest goes into a
    closed fold (|eunoe-truncate|). `false` turns truncation off.

    `chars`         Characters to show before folding the rest.
    `prompt`        Separate limit for prompts; `nil` uses `chars`.
    `reply`         Separate limit for replies; `nil` uses `chars`.
    `open_latest`   Leave the newest reply unfolded.

                                                        *eunoe-config-heading*
heading ~
    What the message headings show, all on by default: >
      6 · You                                                    09:30
<
    `number`      The turn number.
    `separator`   The `·` after the number. Left out when nothing
                  follows the number.
    `icons`       Icons before the names, see below. `false` for none.
    `names`       The speaker's name: "You", "Claude".
    `time`        The time of each prompt, at the right end of its
                  heading: `09:30` today, `Nov 10 09:30` before. Local
                  time.
    `pad`         In one-line mode (|eunoe-modes|), pad the numbers and
                  names to the same width, so the messages line up: >
                     9 · You     commit and push
                     9 · Claude  I committed and pushed both repos…
                    10 · You     tag v0.1.0
<
                                                          *eunoe-config-icons*
heading.icons ~
    Icons before the names. They are Nerd Font glyphs
    (https://www.nerdfonts.com); without a Nerd Font they show as boxes,
    so set `heading = { icons = false }`. Neovim can't tell which font
    the terminal uses.

    `user`    Your prompts. Default: nf-fa-user.
    `agent`   The agent's replies, for every agent. `nil` uses the agent's
              own icon (Claude Code: nf-cod-claude), or nf-md-robot for
              agents without one.

    nf-cod-claude is only in recent Nerd Fonts releases. If the Claude
    icon shows as a box while the others work, update the font or use
    the robot: `heading = { icons = { agent = "\u{f06a9}" } }`.

10. LUA API                                                        *eunoe-api*

All functions are on `require("eunoe")`.

                                                                *eunoe.open()*
eunoe.open({opts})
    Open the split, or refresh it when it is open. {opts}: `all` (boolean)
    shows every turn, like |:Eunoe-all|.

                                                               *eunoe.close()*
eunoe.close()
    Close the split.

                                                              *eunoe.toggle()*
eunoe.toggle()
    Open the split, or close it.

                                                                *eunoe.mode()*
eunoe.mode({mode})
    Switch to `"default"`, `"oneline"` or `"expanded"` (|eunoe-modes|),
    opening the split if it is closed. Without {mode}, return the current
    mode (or, when the split is closed, the one it will open in).

                                                              *eunoe.status()*
eunoe.status()
    Status data of the split in this tab page, or `nil` when it isn't
    open. See |eunoe-status|.

                                                               *eunoe.turns()*
eunoe.turns({opts}, {cb})
    Load the current session's turns, oldest first, and call
    {cb}(`turns`, `session`). For pickers and other plugins. {opts}: `n`
    keeps only the last n turns. Each turn: >lua
      { n = 6, prompt = "…", reply = "…", time = "2026-11-11T09:30:00Z" }
<
    `session` has `id`, `pid`, `reader`, `transcript` and `via`
    (`"parent"` or `"cwd"`, see |eunoe-session|). If no session is found,
    eunoe reports it and {cb} isn't called.

                                                     *eunoe.register_reader()*
eunoe.register_reader({name}, {reader})
    Add support for an agent, replace a reader of the same name, or remove
    one with `false`. See |eunoe-readers|.

11. READERS                                                    *eunoe-readers*

A reader knows one agent: how to find its sessions and how to turn a
transcript into turns. Claude Code is built in (|eunoe-reader-claude|);
other agents can be added with |eunoe.register_reader()|, and get the same
split, folds, quoting and API: >lua
  require("eunoe").register_reader("myagent", {
    detect = function(ctx)
      return {
        { id = "…", pid = 123, via = "parent", transcript = "/path/to/log" },
      }
    end,
    read = function(transcript, cb)
      cb({ { n = 1, prompt = "…", reply = "…" } })
    end,
  })
<
detect({ctx}) ~
    Return the agent's sessions for this Neovim, a list of tables with
    `id`, `pid`, `via` and `transcript`, and optionally `updated` (a time,
    to order several sessions in one directory) and `version`. {ctx} has
    `chain`, Neovim's ancestor pids (nearest first), and `cwd`. Use
    `via = "parent"` for a session whose pid is in `chain`, `via = "cwd"`
    for one running in `cwd`.

read({transcript}, {cb}) ~
    Parse what `detect` put in `transcript` (usually a path) into turns
    (`n`, `prompt`, `reply`, optional `time`), oldest first, then call
    {cb}(`turns`), or {cb}(`nil`, `err`). For a transcript that doesn't
    exist yet, `err` starts with "ENOENT".

Optional fields:
- `label`: a display name, for messages and |:checkhealth|.
- `speaker`: the agent's name in the reply headings ("Agent" without it).
- `icon`: the icon before that name (|eunoe-config-icons|).
- `color`: a `#rrggbb` color for the reply headings (|eunoe-highlights|).
- `tested_version`: the agent version the reader was last checked
  against.
- `health`: a function that gets |vim.health| and adds checks to
  |:checkhealth| `eunoe`.

The nearest agent among Neovim's parents wins across all readers. Readers
registered under the name of a built-in one replace it; `false` removes a
reader: >lua
  require("eunoe").register_reader("claude", false)
<
                                                         *eunoe-reader-claude*
Claude Code ~
    Last checked with Claude Code 2.1.322. Sessions are found through
    `~/.claude/sessions/<pid>.json`; `$CLAUDE_CONFIG_DIR` is respected. The
    transcript format is internal and undocumented, and it changes between
    releases. eunoe skips what it doesn't know instead of failing, so after
    an update it may show less, not break.

                                                                *eunoe-health*
|:checkhealth| `eunoe` compares the running agent version with the last
checked one, and warns about records of unknown types, lines that aren't
valid JSON, and transcripts without turns. Please report these.

12. HIGHLIGHTS                                              *eunoe-highlights*

The headings and boxes are colored by speaker. Colorschemes can define
the groups, and so can you: >lua
  vim.api.nvim_set_hl(0, "EunoeUser", { fg = "#7aa2f7", bold = true })
<
eunoe only defines a group that is unset, or still holds what eunoe set,
so a group set by a colorscheme or by you stays. Set yours after
|:colorscheme|, which clears all groups.

The speaker colors are adjusted to the background: eunoe keeps the hue
and moves the lightness until the color has a 4.5:1 contrast with
|hl-Normal|'s background (the WCAG minimum for text). Claude's orange is
darker on light themes and stays orange. They are computed again after
|:colorscheme| and when 'background' changes. Transparent themes have no
background color, so eunoe goes by 'background'. Each color has a
256-color fallback for terminals without 'termguicolors'.

                                                                   *EunoeUser*
EunoeUser               Your prompts' headings and boxes. Default: slate
                        gray `#8A93A6`, adjusted.

                                                                  *EunoeAgent*
EunoeAgent              The agent's headings, if its reader has no color.
                        Default: linked to |hl-Title|.

                                                            *EunoeAgentClaude*
EunoeAgent{Name}        One group per agent, named after its reader:
                        `EunoeAgentClaude` for Claude Code (default: its
                        terracotta orange `#D97757`, adjusted). Without a
                        reader `color`, it links to |EunoeAgent|.

                                                                   *EunoeTime*
EunoeTime               The time on the prompt headings. Default: linked
                        to `Comment`.

                                                                *EunoeOneline*
EunoeOneline            The start of a message in one-line mode
                        (|eunoe-oneline|). Default: linked to |hl-Normal|.

                                                                 *EunoeFolded*
EunoeFolded             Closed folds in the eunoe window, which maps
                        |hl-Folded| to this group, so one-line rows look
                        like plain lines. Default: linked to |hl-Normal|.

                                                              *EunoeTruncated*
EunoeTruncated          The "… 1,615 more characters" line of truncated
                        text. Default: linked to `Comment`.

13. STATUS LINE                                                 *eunoe-status*

eunoe draws no status line. It exposes data, and you build the component
in lualine, heirline or a plain 'statusline':

- `b:eunoe_status`: a table in the eunoe buffer.         *b:eunoe_status*
- `User EunoeStatus`: fires when the table changes,      *EunoeStatus*
  with the table in `ev.data`.
- |eunoe.status()|: the same table, computed when called.

Fields: >lua
  {
    buf = 12,                -- the eunoe buffer
    agent = "Claude Code",   -- the agent's display name
    reader = "claude",
    session = "77044140-…",  -- the session id
    turns = 41,              -- turns shown
    total = 41,              -- turns in the session
    mode = "default",        -- "oneline", "default" or "expanded"
    turn = 38,               -- the turn at the cursor (nil above it)
    role = "reply",          -- "prompt" or "reply"
    speaker = "Claude",      -- "You" or the agent's name
    loaded = 1794400000,     -- when the session was read (|os.time()|)
  }
<
The cursor fields follow the cursor: the event fires when the cursor moves
to another message, not on every move.

A lualine component, shown in the eunoe window only: >lua
  local function eunoe()
    local s = vim.b.eunoe_status
    return ("%s · turn %s/%d · %s"):format(
      s.agent, s.turn or "–", s.total, s.mode)
  end
  require("lualine").setup({
    sections = {
      lualine_c = {
        { eunoe, cond = function() return vim.b.eunoe_status ~= nil end },
      },
    },
  })
<
A plain 'statusline' for the eunoe window: >lua
  vim.api.nvim_create_autocmd("User", {
    pattern = "EunoeStatus",
    callback = function(ev)
      local s, win = ev.data, vim.fn.bufwinid(ev.data.buf)
      if win ~= -1 then
        vim.wo[win].statusline = ("%s · turn %s/%d · %s"):format(
          s.agent, s.turn or "–", s.total, s.mode)
      end
    end,
  })
<
In heirline, update the component on the event: >lua
  update = { "User", pattern = "EunoeStatus" }
<

14. LIMITATIONS                                            *eunoe-limitations*

- No live updates. In the `Ctrl+G` editor the agent waits for the prompt
  anyway; next to a running agent, press `R`.
- Prompts and replies only. Tool calls, their output and thinking aren't
  shown.
- Subagent conversations are left out. After `/compact`, the earlier turns
  are still shown, as the transcript keeps them.
- Windows is untested.
